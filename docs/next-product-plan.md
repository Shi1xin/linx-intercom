# 下一阶段产品实现计划

后续实施按 [灵矽同频设备与 MCP 接入方案](linx-device-roadmap.md) 推进；本页保留此前的独立对讲固件计划及验收依据

## 交付目标

把现有群语音链路接成可独立操作的设备：待机时按键说出邀请码加入，听到房间名称，通话中通过语音查询、切房、静音和退出。随后完成回声消除和 NFC 实机组队

当前基础实现已提交 [PR #2](https://github.com/Shi1xin/linx-intercom/pull/2)，继续完成 review；下一轮以“真实语音操作与房间播报”作为一个完整交付。产品行为沿用 [产品设计](product-design.md) 和 [产品架构](architecture-design.md)

## 有人值守时先完成的测试

安排一次约 15–20 分钟的现场测试。执行 agent 提前准备设备日志、录音和另一通话端，用户负责按键、说话和判断听感

### 开始前的准备

- 核对当前固件 SHA、实际按键及测试房间；保留原固件备份
- 先处理固定目标识别占位逻辑，使按键采样可独立进行；现有代码松键后可能直接发起切房
- 准备按键触发的原始 PCM 导出，单条录音与用户给出的文本对应；音频保存在 `.local/`
- 准备另一通话端，确认麦克风授权、收发和录音可用；停止合成测试音。另一端使用耳机，现场只有设备外放

### 现场顺序

| 时间 | 用户操作 | 执行 agent 记录与判断 |
| --- | --- | --- |
| 0–3 分钟 | 正常运行时按住命令键 2–3 秒再松开，重复三次；操作实际接好的静音、音量键 | 每次按压与松开各触发一次；采集长度合理；静音与音量变化正确。只有已确认接线的按键参加测试 |
| 3–7 分钟 | 以日常距离和音量说出下面的短句 | 保存设备麦克风原始录音、文本、采样参数；检查首尾截断、削波和可辨识度 |
| 7–12 分钟 | 与另一端轮流讲话，再同时讲话；正常音量后试一次较大音量 | 两端是否听清、首字是否丢失、是否断续；保存回声样例和双方对听感的判断 |
| 12–15 分钟 | 通话中按住命令键说一句话，松开后继续；测试静音和恢复 | 对端录音确认命令内容没有传入房间；设备仍能听到对端；松键及恢复后状态正确 |
| 余下时间 | 试听新完成的房间播报，或触碰已接好的 NFC 标签 | 有对应可运行版本时补验，记录实际完成项 |

采样短句：“房间信息”“静音”“恢复通话”“退出房间”“切到一号房”“切到二号房”，各说两遍；再逐位说出两组不同的六位测试邀请码，其中包含零和重复数字。额外录一次短按无声和一句普通聊天，用于检查误触发。测试码与当前真实房间的对应关系由 agent 记录

今晚的录音先作为识别与音频处理的输入样本。真实识别接入后，再用现场新说的句子和新的邀请码验收

## 实现顺序与阶段 PR

### 阶段 0：收稳当前基础实现

完成当前 PR 的 review 和修复，记录最终源码与实际烧录版本。将真实环境配置移入本地配置，提交通用示例值

已有记录提到“单成员在房约 20 秒后 keepalive 超时”。安排单成员留房、静音和无人讲话各 10 分钟的静默检查，确认控制与媒体连接保持、恢复讲话能收发；复现的断连列为基础实现问题处理

当前 PR 的验收表分别写明协议、媒体、真机、语音和 NFC 的状态。语音识别、播报和回声消除按上表列为后续交付

### 阶段 1：真实语音操作与房间播报

先用约 60–90 分钟验证设备上的识别路径，产出固定命令、房间编号、逐位六位数字的实际结果及资源占用。邀请码用未预注册整句的多组输入测试，尽早确认数字识别能力。识别选型沿用端侧命令处理范围

接通一条完整路径：按住命令键采集 → 真实识别 → 带类型的命令结果 → 执行房间操作 → 本地播报。命令结果覆盖加入、切房、查询、静音、恢复和退出，各自连接已有控制接口

固件实现重点：

- 待机和通话状态都能进入命令采集；待机下可直接说邀请码加入
- 按键采集、识别和操作期间统一管理上行暂停，保留房间收听；操作结束按用户静音设置恢复
- 邀请码保持数字字符串，房间名按编号解析；无声、未识别和无效目标保持当前房间并提示
- 解析入房确认中的名称、人数，以及房间查询中的邀请码；媒体确认就绪后播报入房结果
- 用固定短语、数字和编号拼接预录音，完成房间名、人数、邀请码及操作结果播报；给出音频资源的来源与许可
- 播报和通话播放采用统一调度，处理切房后的旧音频；本地提示与命令音频均保持在本地
- 接入识别后补做超时、连续按键、静音切房、切房失败回原房和退出后重连的状态验证

**本阶段 PR 验收**：在设备上从待机说邀请码加入，听到正确房间名与人数；查询能听到逐位邀请码；按名称切房、静音、恢复和退出均由真实语音触发。至少两个房间、三组未预注册的有效邀请码；每类固定命令三次，逐次记录结果。误识别、误入房和上行泄漏记录为失败并修复

### 阶段 2：外放通话质量与持续运行

接入 AEC，参考信号取实际送往扬声器的 PCM，包含通话音频和本地播报；处理播放与采集的采样率、时序对齐。命令识别也使用处理后的麦克风输入

复用现场录下的样本检查回声与削波，在真机上对比轮流说话和同时说话。以两端听清、无持续回声、无明显首字截断作为演示听感验收；记录处理前后样例以及堆内存、任务负载和缓冲变化

对稳定版本做一次 30 分钟通话及静音交替观察、十次切房和一次断网恢复。分别确认静音设置保持、失败后回原房、主动退出后仍待机

**本阶段 PR 验收**：真实外放双向通话与命令操作共同工作，音频处理后的资源和连续运行记录齐全

### 阶段 3：NFC 组队与最终演示

由已确认的读卡器接入固件，调用现有 NFC 入口。验证房间标签首次建房、重复触碰回同房，以及设备标签加入正在通话的设备、召集待机设备；两端房间状态和播报一致

第二台嵌入式设备接入后做完整双机演示。此前用嵌入式设备与浏览器测试端联调，并在验收记录中标明端类型。NFC 硬件信息集中在本地交接中，语音与通话阶段持续推进

**本阶段 PR 验收**：真实触碰完成组队，随后可以通过邀请码加入、语音切房并继续通话。最终演示固定两房间、三成员，记录每台设备版本和网络路径

## 无人值守期间的工作

现场测试结束后，agent 按上述阶段继续推进，优先交付阶段 1。原任务的结束时间沿用本地交接记录，剩余时间投入当前阶段的修复与验证

- 复用有文本标注的短录音进行识别、参数解析和状态回归；区分开发样本与后续新输入验收
- 生成播报音频，离线检查拼接内容、时长与削波；听感验收留到可出声的时段
- 运行静默连接、接口和媒体隔离检查；设备有声测试集中在用户值守窗口
- 语音模型接入遇到具体问题时留下输入、结果与资源数据，继续推进命令状态和房间播报

每个阶段单独提交可评审的结果。实现 worktree 由同一执行者维护；只读 review 和规划文档保留各自上下文。构建与服务端测试沿用仓库的双机分工

## 交接与下一次验收

在 `.local/` 记录任务 ID、主机、worktree、分支、源码和固件 SHA、模型运行选项、服务地址、job ID、测试证据与下一条操作。用户录音、设备身份和实际网络配置一并保存在本地

每项验证标记“通过 / 失败 / 未执行”。服务端返回房间信息、固件成功解析和扬声器实际播报分别留证；接口切房和真实语音切房分别计时

下一次用户验收使用约五分钟：待机说邀请码加入 → 听房间名 → 查询邀请码 → 静音切到另一已加入房间 → 恢复通话 → 退出 → 再次加入。agent 提前准备两房间和测试对端，并让用户使用新的语音输入完成整条流程
