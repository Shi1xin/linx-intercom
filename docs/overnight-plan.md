# 首版通宵执行计划

## 目标与交付

从 [产品设计](product-design.md) 和 [产品架构](architecture-design.md) 实现一个可演示的群语音闭环：NFC 或邀请码入房、群内全双工通话、按键语音切房、查询、静音与退出

按启动后的八小时安排工作，最后四十五分钟用于验收和交接。时间段是投入预算，阶段提前完成就继续推进；到时交付已验证结果及剩余工作的明确入口

| 交付 | 内容 |
| --- | --- |
| 服务端 | Go 控制服务、SQLite 持久化、Janus AudioBridge 信令适配 |
| 测试环境 | 独立的 Janus、控制服务和 TURN 配置，启动、停止和诊断说明 |
| 设备固件 | ESP32-S3 音频、会话、命令和 NFC 接入；板级参数独立配置 |
| 联调工具 | 最小浏览器测试端，用于多成员音频、房间隔离和设备互通验证 |
| 交接 | 已提交源码、验证记录、运行入口、遗留问题和下一步命令 |

## 产品范围

- NFC 房间标签首次使用建房；设备标签沿用自动组队逻辑，UID 与设备的映射预先登记
- 系统生成唯一的编号房间名和数字邀请码；名称、邀请码及已加入记录持续保存
- 入房播报名称和在线人数；“房间信息”播报名称、人数及逐位邀请码
- “加入〈邀请码〉”进入对应房间；“切到〈房间名〉”进入已加入房间
- 按住命令键识别，期间暂停上行并保持收听；切房保留静音设置，失败恢复原会话
- 退出清除恢复目标，保留已加入记录；断线恢复最近确认的房间

产品范围以这两份设计文档为准。实现中的常规选择由执行 agent 决定，功能取舍保持上述范围

## 执行方式

由一个主 agent 连续推进，串行维护各任务 worktree。服务端、Docker 和部署工作在服务端主机执行，固件、串口和浏览器工作在设备主机执行；实际主机、路径及设备记录见本地交接文件

阶段切换时同步已提交源码，记录双方 SHA；远端构建和测试绑定确切源码版本。长任务使用现有 job 管理入口，恢复时先查询原 job 状态

保留启动会话的模型、reasoning effort、provider 和 profile 选择。运行记录区分配置值与已观测的实际执行情况，恢复上下文时沿用用户最新选择

## 阶段安排

### 0—0.5 小时：建立执行基线

- 创建独立功能分支和任务 worktree，读取规则、设备记录及已有源码
- 记录任务 ID、起止时间、基线 SHA、双机路径、运行选项和授权的测试目标
- 检查音频板级配置、命令键、NFC 接线和可用串口；定位现有固件中可复用的采集、播放、网络及语音模块
- 尽早用录音样例验证固定命令和逐位数字的识别路径，为后续邀请码识别确定具体模块
- 初始化 Go 服务、固件入口及独立测试环境配置，固定依赖版本
- 在 `docs/control-protocol.md` 约定最小消息格式：设备身份、请求 ID、入房目标、静音、房间信息、退出、会话结果及 SDP/ICE 转发

产物：可复用的任务目录、依赖清单和共同协议。未知板级参数记录为具体缺口，继续推进服务端与联调工具

### 0.5—2 小时：打通真实音频

- 在独立测试环境启动 Janus AudioBridge，建立 Go 控制通道到 Janus 的会话和信令转发
- 建立最小浏览器测试端，使用测试设备身份连接同一控制服务
- 两个测试端进入同一房间，验证 Opus 上下行及实际音频接收；扩展到第三个成员验证混音
- 打通 `changeroom`，准备两个房间；确认切房后收发声音来自目标房间
- 配置可访问的媒体地址和端口，记录 ICE 选中的候选路径；TURN 另做强制中继验证

验收：真实 Janus 会话、媒体收发证据及两个房间的隔离结果。浏览器端作为工程联调工具保留在 `tools/`

### 2—3.5 小时：完成房间业务

- 实现设备、NFC 入口、房间、成员记录及活动会话的数据模型
- 实现 NFC 房间创建、设备标签组队、邀请码加入、已加入房间切换和房间信息查询
- 持久化名称、邀请码和静音设置；退出保留成员记录，重启后恢复房间映射
- 将入房、切房和退出接到真实 Janus，媒体连接成功后确认当前房间
- 测试重复请求、同一标签并发建房、无效邀请码、未加入房间、切房失败、静音保持和主动退出后的恢复行为

验收：通过接口和真实媒体联调完成“建房 → 加入 → 查询 → 切房 → 退出 → 再次加入”，关键边界有自动化测试

### 3.5—5.5 小时：接入嵌入式设备

- 接入已核实的板级音频与按键配置，完成麦克风采集、扬声器播放、Opus、回声消除和媒体会话
- 设备通过同一控制协议进入房间，与浏览器测试端双向通话
- 使用已授权的测试设备完成固件备份、校验、烧录和串口观察，记录固件 SHA、板型及构建配置
- 接入已具备的 NFC 读卡器，复用服务端入口解析；原标签内容保持原样
- 完成断线恢复、退出、播放缓冲清理和静音状态保持

验收：至少一台嵌入式设备参与真实通话；记录内存、音频连续性和恢复结果。设备或板级资料缺失时，完成可构建固件、适配接口和浏览器联调，并列明需要补充的引脚或器件信息

### 5.5—7.25 小时：接入语音并完成场景联调

- 实现“静音”“恢复通话”“房间信息”“加入〈邀请码〉”“切到〈房间名〉”“退出房间”
- 房间名按编号解析，邀请码按数字序列解析；数字位数和读法与服务端分配规则一致
- 分别验证固定命令和邀请码数字识别，测试包含未预注册整句的邀请码
- 按键进入命令模式时立即暂停上行；结果播报后按用户静音设置恢复通话
- 连接三名成员、两个房间，覆盖 NFC 与邀请码入房、语音切房、静音切房、无效目标、断网及主动退出
- 对已稳定的版本做一次连续通话观察和连续切房检查，记录实际次数、耗时和失败详情

验收：音频与识别经过真实输入链路；语音命令未传入群内，切换后声音归属正确。工具注入的命令用于协议测试，验收记录单列真实语音结果

### 7.25—8 小时：收尾交付

- 停止增加功能，修复影响演示的已知问题
- 对最终改动执行所需检查；同一源码版本复用已通过的结果
- 检查 diff、配置来源、文件权限和凭据处理，提交已验证改动
- 保存运行入口、服务地址、job ID、设备固件版本和日志位置，保留本次可演示测试环境
- 更新仓库运行说明；在本地交接文件写明完成项、验证证据、遗留项和下一步命令

## 验收记录

| 项目 | 证据 |
| --- | --- |
| 构建与测试 | 最终 SHA、执行主机、命令、结果 |
| 三方群语音 | 三个参与端身份、真实收发记录、混音结果 |
| 房间隔离 | 两个房间、切换前后参与关系及音频接收结果 |
| NFC | 实际读卡结果、入口类型、重复触碰后的房间关系 |
| 语音命令 | 输入语句、识别结果、执行结果、失败样例 |
| 恢复与退出 | 中断位置、恢复目标、静音状态、主动退出后的状态 |
| 运行质量 | 通话延迟、切房耗时、连续运行时间及设备资源变化 |
| 网络路径 | 测试网络、ICE 候选、直连或 TURN 路径；4G 另列实测结果 |

每项标记为“通过”“失败”或“未执行”，附对应证据。模拟接口、浏览器通话和硬件通话分别记录

## 阻塞处理与续跑

同类失败连续三次后重新检查输入、依赖和方案，并留下复现命令。硬件接线、凭据或外部服务不可用时，先完成其余可执行项；待补条件集中记录到交接文件

| 情况 | 继续推进的工作 |
| --- | --- |
| 真机断开或板级参数缺失 | 固件构建、协议与状态机测试、浏览器媒体联调 |
| NFC 读卡器缺失 | 邀请码加入、NFC 事件处理与幂等测试 |
| 4G 路径暂不可用 | 已有 Wi-Fi 路径联调，保留实际 4G 接入和网络诊断记录 |
| 数字邀请码识别未通过 | 固定语音命令、识别适配及用例，保留数字识别复现输入 |
| 远端任务连接中断 | 查询原 job 状态和日志，接续原源码版本与工作目录 |

任务恢复时先读取交接文件，确认原 job、worktree、分支及 SHA；继续第一项未完成工作。达到八小时预算后完成交接，后续执行从已记录入口继续
