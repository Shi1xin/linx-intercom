灵矽平台 · 多人实时语音房间

一台设备，
两路对话。

给灵矽平台加上群语音能力。对设备说一句话就能新建房间、用邀请码加入、按名字切换；房间成员之间全双工通话；其他灵矽智能体也能把设备拉进房间。

两路对话

设备平时是灵矽助手。进入房间后，它同时承载对房间和对智能体两路对话，各走各的通道。

对房间说

直接开口

  • 房间全员实时听见，可以同时说话
  • 双击 BOOT 静音，静音时继续收听

对智能体说

按住 BOOT，或说「你好小智」

  • 房间上行暂停，房间声音继续播放
  • 智能体的回复只在本机播放

开车时最频繁的动作是和队友说话，所以它零操作；对智能体的命令频率低，用明确的触发防止误操作。

建群与入房

房间持久存在。系统按顺序起名「一号房」「二号房」，配六位数字邀请码，都能用语音说清楚。邀请码是首次进入的凭证，只告诉要拉进来的人；房间名只用于切回自己加入过的房间。

语音新建

「新建一个对讲房间」

智能体念出房间名和邀请码，转告队友即可。

邀请码加入

「加入对讲房间，邀请码七二三八二七」

首次进入别人的房间。

按名切换

「切换到二号房」

回到加入过的房间，静音设置保留；切换失败时留在原房间。

云端调用

另一个灵矽智能体调用 intercom.*

调度员远程把设备拉进房间、切房、退出，设备本地播报去了哪里。

NFC 碰一碰

设备碰标签，或两台设备相碰

第一次碰标签建房，之后碰进同一房间；碰到正在通话的设备就加入对方。

执行链完成 · 读卡器待接

自动恢复

断线或断电重启

回到最后所在的房间；主动退出后保持待机。

扩展灵矽，平台侧零改动

智能体负责控制：听懂意图、调用房间工具、说出结果。房间服务负责媒体：群语音经 WebRTC 直连语音房间，在服务端混音，通话时长与平台调用成本无关。

用户说话→灵矽智能体→MCP 工具→房间执行器→语音房间

设备侧 MCP

self.intercom.*

设备绑定的智能体随会话发现这些工具，用户对设备说话即可操作房间。

云端 MCP

intercom.*

任意灵矽智能体配置同频服务后，可以远程操作指定设备。

mcpproxy 反向通道

平台官方通道

同频服务主动连出并注册云端工具，部署时无需公网入口。

设备身份、OTA 激活、账号绑定和 ASR/LLM/TTS 沿用平台现有流程。两套工具落到设备上同一个房间执行器，新增一项房间能力只需加一条命令。

语音就是界面

用户全程看不到屏幕，每一句反馈都必须和设备真实状态一致。

说出的就是实际状态

工具结果在语音接通、服务端确认之后才返回。智能体报出的房间名和在线人数就是设备实际所在的房间，失败时说明原因。

被远程移动时有播报

云端调用或 NFC 改变了房间时，设备用本地提示音和播报说明结果；自己用语音触发时，让位给智能体的回答。

设置跟着设备走

静音和所在房间持久保存，切房、断线、重启后保持。
